# Response to the 2026-10-17 reviews

Two reviews were received: a principal-engineer spec review (findings C, H, Medium, process) and a staff security review (findings S-01 to S-20). This document records the owner's decisions on them and maps every finding to its disposition and the requirements that implement it.

**Dispositions:** **Accepted**: done as proposed. **Adapted**: the intent is met by a different mechanism. **Declined**: not adopted; the reason and any recorded risk are given. **Open**: tracked as an open question.

## Owner decisions taken with this response

| Decision | Result |
| --- | --- |
| Q-03, CLI implementation | A single compiled **Rust** binary with signed releases (D-32). The reviews suggested Go; Rust meets the same goals |
| Instance integrity | Hosts apply **signed commits on `main`**. No signed instance release tags and no canary ring. The residual risk is accepted and documented (D-37, threat model) |
| Q-11, upgrades | Security updates automatic on every class; feature and OS upgrades only in maintenance windows (D-40) |
| Q-12, visibility | Instances start private; public instances are an M8 feature (D-41) |
| Scope | Kubernetes, Talos and Flatcar cut from the engine (D-38). Netboot, Fedora Atomic and push remain in M7, before 1.0 |
| Q-10, Q-15 | Left open. The security parts of Q-15 (owner must equal login; no auto-select unattended) are adopted in BOOT-07 |
